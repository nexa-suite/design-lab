# Nexa Design Lab v0.8 — Component Maturity

## Maturity vocabulary

| Status | Meaning | Required evidence |
| --- | --- | --- |
| EXPERIMENTAL | Hypothesis or lab infrastructure | Visible question and open decision |
| CANDIDATE | Reviewable visual and interaction contract | Live specimen, states, API and focused validation |
| FROZEN | Human direction protected from casual drift | Explicit decision before visual change |
| DEPRECATED | Not for new work | Replacement or historical boundary |

Maturity is documentation metadata. It is not a production feature flag, accessibility certification or domain approval.

## Frozen direction carried from v0.7

- Design Lab sidebar: grouping, search, active row, blue leading cue, spacing, PrimeIcons and mobile drawer behavior.
- Text Field: geometry, padding, label relationship, focus treatment and semantic support copy.
- Light appearance, blue identity, slate hierarchy and candidate type families.
- Action Menu direction: quiet trigger, raised menu, command semantics, keyboard path and focus restoration.
- Canonical supplied Nexa logo usage through `NexaLogo`.

## Candidate controls and patterns

Buttons, fields, selection controls, Status, Alerts, Menus, Tooltips, Dialogs, Cards, Tables, Progress, Workflow, Quantity, Slider and Navigation remain candidate specimens with different interaction depth.

v0.8 adds candidate evidence for:

- Async Operations: happy, warning/cancel and failure/retry sequences;
- Authentication: canonical branding, localization and safe validation states;
- Legal Content: synthetic long-form structure and formal approval boundary;
- Payments: masked synthetic data, empty/loading/unavailable and diagnostic separation;
- Analytics: question → visual → summary → table/no-data grammar;
- Dispatch Board: card/column states and command-equivalent movement path;
- Data-Dense Operations: generic operational table states without an Inventory contract.

## Experimental infrastructure

Evaluation modes, state galleries, local simulation signals and the State Sequence remain experimental lab infrastructure. They prove behavior for review; they are not production APIs.

## Promotion checklist

Before production ownership, human reviewers must confirm purpose, semantic boundary, variants, keyboard/focus/target/reflow/reduced-motion behavior, token ownership, contrast, API independence, tests, browser evidence, Figma mapping and repository ownership.

No v0.8 page performs that promotion or design-audit decision.
